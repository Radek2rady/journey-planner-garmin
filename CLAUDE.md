# Transit

Journey planner for Garmin watches (Connect IQ, Monkey C), target device Forerunner 955.
The user picks an origin (GPS position or a stop) and a destination stop; the watch shows
the next connections for the whole Czech Republic, with delays and platforms.

Read `docs/PLAN.md` for where the project is heading and `docs/TASKS.md` for what is done
and what is next. Keep both current: they are part of every change.

## Architecture

```
watch app  --BLE-->  phone (Garmin Connect)  --HTTPS-->  proxy  --HTTPS-->  api.transitous.org
```

A watch app can only take responses of a few kB; Transitous returns ~170 kB per search.
The proxy forwards the query and returns a compact JSON (`docs/API.md`, ~2 kB).

| Path | Responsibility |
| --- | --- |
| `source/TransitApp.mc`, `source/AlertService.mc` | Lifecycle, glance view, background service of the departure alert; `AppServices` (`api`, `location`, `trip`, `favourites`, `savedSearches`) via `getServices()` |
| `source/model/` | `Stop`, `Trip`, `SearchFilters`, `Leg`, `Connection`, `ConnectionsPage`, `SavedSearch`, `Departure`, `DepartureBoard`; parsing of the wire format |
| `source/data/` | `TransitApi` (HTTP), `LocationProvider` (GPS), `TripStore`, `Favourites`, `SavedSearches` (persistence); `GlanceData`, `StorageKeys` (read by the glance) |
| `source/ui/` | Views, menus and their delegates; `Texts` turns data into localized text |
| `source/test/` | Watch unit tests (`(:test)` functions) |
| `resources/`, `resources-ces/` | Strings: English is the default, Czech the translation |
| `source/BuildConfig.mc` | Generated by the Makefile (proxy address and key); never edit or commit |
| `proxy/` | `transit_proxy.py` (stdlib only) and its unit tests |
| `proxy/api/`, `proxy/vercel.json` | Entry points and settings of the hosted proxy (`docs/DEPLOY.md`) |

Dependencies point one way: `ui` -> `data` -> `model`. `model` and `data` never load
resources or touch `WatchUi` (exception: `LocationProvider` requests a redraw).

## Commands

```
make build        # debug build, strict type check
make test-proxy   # proxy unit tests
make test-watch   # watch unit tests; needs `make simulator` running
make proxy        # proxy on http://127.0.0.1:8787
make run          # run in the simulator; needs `make simulator` and `make proxy`
make release      # bin/Transit-release.prg for the watch; needs PROXY_URL in local.mk
```

`DEVELOPER_KEY` defaults to `~/Documents/garmin-key/developer_key`; override it on the
command line when the key lives elsewhere.

## Conventions

- English everywhere: identifiers, file names, comments, docs, commit messages.
- No user-visible text in code. Add a string to `resources/strings/strings.xml` and its
  Czech translation to `resources-ces/strings/strings.xml` in the same change.
- The proxy returns codes (`"bus"`, `"bad_request"`), never wording. Mapping to text
  happens in `source/ui/Texts.mc`.
- Type check is strict (`project.typecheck = 3`). The build must have zero warnings.
- Classes parse and hold data; raw dictionaries from JSON do not leave `model/` and `data/`.
- Logic that can be tested without a device is written as a static or module function
  and covered by a test (`source/test/` or `proxy/test_transit_proxy.py`).
- A change to the wire format updates `docs/API.md`, the proxy, the model parser and the
  tests of both sides together.
- Git: only the user runs commands that change the repository or the remote (`git init`,
  `add`, `commit`, `push`, ...). Assistants may run read-only commands such as `git diff`.
- Privacy: positions and search terms are never logged. No secrets or keys in the repo.

## Definition of done

1. `make build` succeeds without warnings.
2. `make test` passes; new logic has tests.
3. The flow was exercised in the simulator (and on the watch for device-specific changes).
4. Both string files are in sync.
5. `docs/TASKS.md` is updated; `docs/PLAN.md` and `docs/API.md` when affected.

## Gotchas

- The app is a `widget` (manifest), not a `watch-app`: on the fr955 watch-apps sit in
  the activity list behind START, which is blocked while an activity runs or is
  suspended with *Resume Later*. A widget opens from the glance loop on the watch face.
- From API 4.0 an app appears in the glance list only with its own `getGlanceView`. In
  glance mode (64 kB) only `(:glance)` code and `scope="glance"` strings are loaded, so
  the services live in `AppServices`, created on first use (`getServices()`), never in
  the glance. Full-app methods of `TransitApp` carry `(:typecheck(disableGlanceCheck))`.
- The app class is `(:glance, :background)`. The background service (`AlertService`,
  64 kB) loads only `(:background)` code and no resources: the alert texts are built by
  the app and stored with the alert (`DepartureAlert`). The watch keeps one scheduled
  background event per app, so there is one alert at a time.
- Requests over Wi-Fi exist only in sync mode: `WifiSearch` stores the query and calls
  `startSync2`, the watch closes the app and runs `WifiSyncDelegate` (no UI, no
  `getServices()`, which would start the GPS); the result goes to the saved searches.
- The glance reads storage directly (`GlanceData`), not through `Favourites` or
  `SavedSearches`. A change to their storage format must update `GlanceData` too. The
  glance makes no requests: the fr955 redraws it only now and then into a cache, so a
  late response would never show.
- Changing the app type made the watch install Transit anew: stored data was lost.

- Simulator and plain HTTP: uncheck *Settings > Use Device HTTPS Requirements*, otherwise
  requests to `http://localhost:8787` fail with error -1001. A real watch needs a public
  `https://` URL; it is set in `local.mk`, see `docs/DEPLOY.md`.
- Do not use `WatchUi.TextPicker`: in the fr955 simulator a click on it crashed the app
  with "Failed invoking <symbol>" and an empty stack. Stop names are typed in the own
  `StopNameEntry` view.
- On the fr955 a long press of DOWN opens the music controls and of UP the menu
  (`onMenu`); an app cannot use a held DOWN.
- `Menu2` cuts long labels with "..." and does not scroll them. Keep sub-labels within
  `Texts.SUMMARY_BUDGET` characters or offer the full text on a separate view.
- Stored data outlives the code: a changed storage format gets a new key (see
  `SavedSearches`), because reading the old shape is a fatal error, not an exception.
- Menu item ids are symbols (`:search`). Do not give a private method the same name, the
  compiler warns about the collision.
- `Storage.setValue` wants `Storage.KeyType` / `Storage.ValueType`; see `TripStore`.
- `monkeydo` does not exit after `make run`; stop it with Ctrl+C.
- `monkeydo -t` exits with 1 even when every test passes; `make test-watch` therefore
  judges the run by the `PASSED` line of its output (`bin/test-watch.log`).
- The simulator sometimes crashes (segfault inside the simulator) after a test run has
  printed its results; it does not affect the results. Every recorded crash happened
  while VS Code with the Monkey C extension was running; the first run with VS Code
  closed did not crash. Likely cause, not yet proven: run the watch tests with VS Code
  closed. Stopping web requests, location and timers in a last test did not help.
- A single test runs with `monkeydo bin/Transit-test.prg fr955 -t <testName>`.
- Transitous counts `maxTransfers` one higher than the number of changes; the proxy
  compensates and enforces the limit on the result (`search_connections`).
- A new proxy endpoint needs its own function file in `proxy/api/`, otherwise it exists
  locally but not on Vercel.
- Transitous is a free community service: keep request volume low and the `User-Agent`
  in the proxy meaningful.

## Verification
- Always: `make build` (zero warnings) and `make test-proxy`.
- Watch logic changed: `make test-watch` (needs `make simulator`; judge by the `PASSED` line in `bin/test-watch.log`).
- The manual steps of "Definition of done" (simulator, string files) are reported as not run unless done.
